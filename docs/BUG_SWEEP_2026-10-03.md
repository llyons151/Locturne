## Fixed in this sweep

1. **The web preview crashed on Home, You, Wake, Scan and Exits** (`getLimits().map is not a function`).
   - **Cause:** seven readers in `lib/screen-time.ts` called the library's `userDefaultsGet` directly. Off iOS, the library's stub returns a Promise.
   - **Fix:** they now go through `sharedGet`, like every other read.
   - **Test:** `screen-time.web.test.ts`. It fails on the old code.
   - **Side effect:** `passes.test.ts` and `scan.test.ts` had relied on that leak to read the fake's armed night. They now arm through `sharedSet` (`fake.armedNight()`).
2. **Paywall bypass through the Routine tab.**
   - **How it worked:** someone could leave onboarding at the paywall, since setup is saved. Then any Routine edit called `armRoutine()`, which armed tonight with no subscription.
   - **Fix:** the Routine tab now re-arms only when something is already armed. Otherwise it goes through `armIfPaid()`.
3. **The deep-link exit offer.** In release builds, `locturne://onboarding?step=declined&exit=half-price` opened the half-price offer for anyone, as often as they liked. `?step` and `?exit` now apply only in dev builds and on the web preview.
4. **The Home gear opened onboarding in the App Store build.** That showed subscribers the paywall, and leaving it rewrote their routine through `saveSetup`. The gear now shows only in dev builds and on the web preview, until there is a real settings screen.
5. **Step count froze after coming back from the background.**
   - **Example:** 50 live steps, 100 more in the background, then 30 more live. The screen showed 150 instead of 180 until the next 10-second poll.
   - **Fix:** `lib/wake/steps.ts` banks the steps the watcher missed (`away`) on the first history read after a restart only. Ordinary polls still can't double-count live steps, and the cadence cap is unchanged.
   - **Tests:** 2 new.
6. **A Block now whose end iOS never delivered stayed shielded, while the app showed it as over.**
   - **Fix:** `syncLock` now tidies an expired nap (`getNap()`) on every sync.
   - **Test:** in `lock-controller.test.ts`.
7. **"Pick another way" on the walk left edit mode stuck.**
   - **What happened:** `edit('method')` set `returnTo='walk'`, but `method` wasn't in `EDITABLE`. Every later step's button said "Save" and jumped back to the walk. Tapping Back on `apps` silently restored `method: 'steps'`.
   - **Fix:** `method` was added to `EDITABLE`.
8. **The two `set-state-in-effect` lint errors in the walk (onboarding-flow).** They are now set while rendering, React's "adjusting state when a prop changes" pattern. The haptic stays in an effect, so the page no longer draws a stale frame.
9. **The Swift limit day key used `Calendar.current`.**
   - **What happened:** on a phone set to Japanese, Buddhist or Hebrew dates it wrote `0008-10-03`, `2569-10-03` or `5787-01-22`. JS never matched these, so used-up limits read as not used up and overlapping rules unshielded them.
   - **Fix:** the key is now always Gregorian.
   - **How it was checked:** the function was compiled and run with Swift 6.2 Foundation.
10. **`ShieldConfigurationExtension.swift` force-unwrapped `token!` four times.** A nil token would crash the extension, and iOS would fall back to its generic shield. It now uses `token.map { … } ?? ""`.
11. **New `features/onboarding/estimate.test.ts`.** It has 17 tests covering the value-number math: midnight and shift bedtimes, the 3 h/14 h schedule edges, zero minutes, age past the lifespan, wording, and `isInsideBedtime`. No math errors were found.

## Second pass, same day: the open items

Decisions taken (2026-10-03):
- A subscription that ends disarms from the next bedtime. It never unlocks mid-night.
- Block now, the always list and daily limits need a subscription too.

### Fixed

**Revenue and App Review**
- **No subscription, nothing blocks.**
  - `settleSubscription` runs at launch, on every return to the app, and on purchase, restore or Ask to Buy approval.
  - Without a subscription, a night or morning under way finishes first. Then `standDown` stops the night windows, Block now and the limits, and wakes every list. All settings are kept.
  - The extension skips re-shielding while stood down. `standUp` brings it all back.
  - Home says "No subscription, so nothing sleeps" and offers See plans. You and Apps offer the same.
  - All three open `/onboarding?resume=paywall`, which shows the offer with the saved times. Before this, a declined user had no way back to the paywall in a release build.
- **`saveSetup` keeps nights off and the step goal** instead of resetting the routine.
- **The trial reminder uses the store's trial end** (7 or 14 days), for any plan. "Remind me" asks for notifications.
- **A production EAS build fails without a real `appl_` key** (`app.config.js`), and release builds refuse `test_` keys.
- **Double-tap purchase is ignored.** Ask to Buy approval moves the open paywall on.
- **No morning promise for a morning already unlocked** (emergency, pass) or one armed too late. A new proof reschedules the notifications.

**Lock correctness**
- **The morning shield works with the app closed.**
  - The app keeps a `locturne-morning` shield (morning words plus the tap notification) up to date.
  - The extension copies it onto the bedtime list when the last window ends at morning start, if the night is still held.
- **A limit used up on an earlier day is lifted on app open.**
- **Limit edits are saved only once iOS accepts them** (Apps tab and the bedtime settle). A refused loosening stays pending and is retried.
- **Nap shield words come from `syncLock`,** and Home shows a running Block now.
- **A nap across the autumn clock change is refused.** Spring is fine.
- **Bedtime picker during an emergency-paused night** no longer re-blocks the apps.
- **Settle race:** only an explicit `empty` flag empties a list. A missing draft no longer does, in JS or Swift.

**Smaller**
- **Downstairs uses the real Motion permission,** and Start can't leak listeners.
- **Wake screen:**
  - keeps the display on only while a method is showing;
  - reads the routine fresh;
  - shows the scan link only with a code, and pushes it.
- **You tab** refreshes passes, the trial and the plan on focus. **Home's tonight line** uses a waiting edit.
- **VoiceOver labels** on the iOS segmented control and the limit menu.
- **Self-check:** heartbeats record whether the bedtime list had apps, so an empty list is flagged even with the always list shielded.
- **Waitlist:**
  - the time trap uses the page's own elapsed time;
  - early `content-length` check;
  - emails starting with `= + - @` are refused.
- **A notification tap** doesn't stack a second wake screen.

## The extension runs on Linux now (2026-10-03)

Until now, the monitor extension's Locturne code only ran on a real iPhone. That code decides
what sleeps while the app is closed. `npm run test:native` ([native-tests/](../native-tests/README.md))
now compiles the real `DeviceActivityMonitorExtension.swift` and the library's `Shared.swift`
against stand-ins for Apple's frameworks, and runs two sets of checks.

**24 Swift scenarios** cover:
- bedtime;
- off nights, including windows after midnight belonging to the evening before;
- a routine edit due at bedtime, with iOS starting the window a minute early;
- an unreadable routine (it still locks);
- shift-worker nights;
- the morning words and their tap, with iOS ending the window a little late or early;
- nap, limit and always-list overlaps on iOS's one blocklist;
- list edits waiting for bedtime, including the `empty` flag;
- the emergency pause through the rest of the night and back at the next bedtime;
- stand-down;
- the heartbeat;
- the Gregorian day key.

**9 handoff fixtures** come from `src/lib/native-handoff.test.ts`. That test drives the real
app code and saves the App Group exactly as the library would leave it. The Swift side then
replays every callback iOS would make with the app closed. After each one, it must shield
exactly what `readLock` says. On a limit's threshold, it must also write the key and value
`limitUsedUpToday` reads. Scenarios:
- two nights;
- weekend off;
- a routine edit;
- removing an app;
- an emergency at 00:30;
- a limit with Block now;
- a lapsed subscription;
- both clock changes.

**Results:**
- All 33 checks pass in UTC, New York, London, Chatham, Santiago, Lord Howe and Kolkata.
- No bugs found in the extension or the handoff.
- **The tests can fail:**
  - With the Locturne logic broken on purpose (no stand-down check, wrong evening,
    no 2-minute slack, settle ignoring `empty`, no morning window check), the Swift
    scenarios fail.
  - With an App Group key renamed on the Swift side (`routine`, `pendingLists`, `stoodDown`,
    `limits`, `limitReached`, the nap's `end`), the handoff replays fail.

**Notes:**
- **Library trap, not a bug today.** `cleanUpAfterActivity(name)` clears keys by prefix, so
  `limit-1` would also wipe `limit-10`'s actions. It's safe while `MAX_LIMITS` is 3 and night
  windows are only cleaned up together (native-tests/README.md).
- **A stray window start while stood down:** fixed the same day (see the simulation section).
- **Not covered:** iOS's own timing, the extension's memory limit, the real shield screen and
  the real `ManagedSettingsStore`. Those still need the device script.

## Multi-day lock simulation (2026-10-03)

`src/lib/lock-controller.sim.test.ts` replays seeded runs of 7–14 days through the real app
entry points (launch and foreground, wake screen, exits, Block now, Routine and Apps tabs,
paywall). It runs them against `src/lib/sim-device.ts`, a simulated iPhone with iOS's one
blocklist, a clock-driven scheduler, dropped callbacks, and a JS port of the monitor
extension. What's shielded is read from that device. It's checked against an oracle built
from the product rules:
- no lock before purchase;
- stand-down after a lapse;
- proofs, passes and the emergency unlock;
- edits wait for bedtime;
- nights off;
- naps end;
- limits lift at midnight and never loosen early;
- removals wait.

`npm test` runs 300 seeds plus the 22 seeds that found something, in about 4 s.
`LOCK_SIM_SEEDS=3000 LOCK_SIM_DAYS=14` is the heavy run: about 45 s a zone, clean in the
5 `test:tz` zones plus Chicago, Tokyo, Lord Howe and Kolkata. A failure is shrunk to a
minimal action list. Mutations of 16 lock rules were all caught.

**Fixed (each with a regression test):**
1. **A lapsed subscription locked every night after it** if nobody proved the morning under
   way (it lasts until bedtime, then the next night is a night too).
   - Seeds 24 and 156 (a flight west).
   - `settleSubscription(false)` now remembers the morning under way
     (`locturne.subscriptionEndedMorning`) and stands down on any later one.
   - It's in `settleSubscription`, not `syncLock`, so an open after a renewal never stands
     down on the stale answer (seed 165).
   - Tests: `lock-controller.test.ts`.
2. **Subscribing again during an emergency pause armed nothing** (`no-apps`). The picks were
   parked in the draft.
   - Seed 39.
   - `armTonight` and `armIfPaid` now count `shownSelection('night')`.
   - Test: `arm.test.ts`.
3. **An earlier bedtime on an evening that's off ended an unproven morning early, from bed.**
   - Seed 193.
   - Windows armed ahead of the edit are skipped by the extension (it reads the routine in
     force), and a skip unshields.
   - `planArming` now defers those until the edit applies.
   - Test: `wake/arming.test.ts`.
4. **Re-arming dropped the armed record while iOS registered the windows.**
   - Seed 543.
   - A sync in that gap read the morning as free, or stood down under the arm, which then
     armed anyway.
   - `armNight` keeps the record, and `arm()` backs out if a stand-down landed meanwhile.
   - Tests: `screen-time.test.ts`, `lock-controller.test.ts`.
5. **An emergency pause ended mid-night when a list edit was due inside it.**
   - Seed 714.
   - An edit made with nothing armed starts at midnight.
   - `pauseNightUntil` and the paused branch of `finishListEdit` now bring the list back
     exactly when the pause ends.
   - Test: `emergency.test.ts`.

**Swift: fixed the same day** (`DeviceActivityMonitorExtension.swift`, mirrored in `sim-device.ts`).
Each has a native-tests scenario that fails on the old Swift.
- **A window the spring clock change pushes past morning start** (seed 177) used to count as
  the next evening's night. It shielded an off night's free morning, or re-shielded after a
  proof.
  - Now `locturneWindowNight` places each window by the *armed* times. A window outside its
    night changes nothing if another window of that night already ran (from the heartbeat
    log).
  - If it was the night's only window, it still locks that night (a 02:30–03:00 night on
    spring day).
  - The sim's strict test is no longer skipped.
- **Stale windows** (seeds 486, 1304) used to skip a night by the new routine's nights and
  release a morning nobody proved, while the new routine still held it.
  - Windows are now placed by the armed times.
  - A skip releases the night only inside the night of the routine in force
    (`locturneInsideNightInForce`). Otherwise it does nothing.
- **No subscription, app closed:** a night window whose morning comes after
  `locturne.subscriptionEndedMorning` now skips. That's the same rule as
  `underWayWhenEnded`.
  - An early window armed for a waiting edit doesn't release, because the morning under way
    hasn't ended under the routine in force (seed 318).
- **Stood down:** a stray window start is ignored and holds nothing, so `standUp` can't
  shield the bedtime list in the day.
- **iOS starting a window early:** the allowance is now 2 minutes, matching the
  pending-edit slack. With 5 minutes, a window 5 minutes before the in-force bedtime
  released too early (seed 66, Chatham).
- **The heavy sweep is clean:** 3000 seeds × 14 days, in UTC, New York, Chicago, London,
  Chatham, Santiago, Tokyo, Lord Howe and Kolkata.
- **Still slack in the sim:** stale windows. After an edit, lock-state re-reads a morning
  already proven under the old times and may call it locked again (seeds 368, 654, 1431,
  listed below). The extension can't know that, and it's a product call.
- **Needs a device build to confirm.**

**Tolerated edges, worth a decision:**
- **Skipped bedtimes:** lock-state starts a skipped bedtime an hour late (02:30 becomes
  03:30), while the windows fire on the wall clock (seeds 63, 265).
- **A routine change re-reads the morning:** when the new routine takes over, it re-reads the
  morning that just passed with its own start. A proof made before the new start stops
  counting, so `readLock` calls a stretch of the evening an unproven "morning" (seed 368).
  Nothing shields with the app closed, but an open would.
- **Flights:**
  - An emergency pause ends at the old zone's bedtime.
  - Windows armed early for a waiting edit can fire as a phantom night in the new zone until
    the next open (seed 852).
  - Flying back over midnight makes "used up today" ambiguous.
- **Unpaid users can trigger the emergency pause:** `previewEmergency` offers a night pause
  to a stood-down (or never-paid) user, although nothing is asleep. It's harmless now (fix 2
  covered the consequence), but the exits screen could say "nothing is asleep" instead.

## Rerunning the tools

- **Lock simulation:** `LOCK_SIM_SEED=<n>` replays one seed. `LOCK_SIM_DEBUG=1` logs the
  shrunk run. `LOCK_SIM_COVERAGE=1` prints how often each path ran.
- **Native tests:** `npm run test:native` (or `test:native:tz`). On this machine:
  `SWIFT_TOOLCHAIN=~/.local/share/swift-6.2/usr LD_LIBRARY_PATH=~/.local/share/swift-6.2/lib`.

- **Web crawl:**
  - Run `npx expo export --platform web --output-dir <dir>`.
  - Serve it with clean URLs (e.g. `serve-handler`).
  - Open every route and `/onboarding?step=<id>` in Playwright Chromium with `devices['iPhone 15']`.
  - Collect `pageerror`, console errors and failed requests.
  - WebKit won't launch on Arch (it needs Ubuntu system libraries); Chromium is fine for the preview.
- **Swift parse on Linux:**
  - Use the swift.org Ubuntu 24.04 tarball.
  - It needs `libncurses.so.6`. On Arch, symlink `/usr/lib/libncursesw.so.6` into a folder on `LD_LIBRARY_PATH`.
  - Then run `swiftc -parse <file>`.
