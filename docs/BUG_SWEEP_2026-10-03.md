## Fixed in this sweep

1. **The web preview crashed on Home, You, Wake, Scan and Exits** (`getLimits().map is not a function`).
   - **Cause:** seven readers in `lib/screen-time.ts` called the library's `userDefaultsGet` directly. Off iOS, the library's stub returns a Promise.
   - **Fix:** they now go through `sharedGet`, like every other read.
   - **Test:** `screen-time.web.test.ts`. It fails on the old code.
   - **Side effect:** `passes.test.ts` and `scan.test.ts` had relied on that leak to read the fake's armed night. They now arm through `sharedSet` (`fake.armedNight()`).
2. **Paywall bypass through the Routine tab.**
   - **How it worked:** someone could leave onboarding at the paywall, since setup is saved. Then any Routine edit called `armRoutine()`, which armed tonight with no subscription.
   - **Fix:** the Routine tab now re-arms only when something is already armed. Otherwise it goes through `armIfPaid()`.
3. **The deep-link exit offer.** In release builds, `locturne://onboarding?step=declined&exit=half-price` opened the half-price offer for anyone, as often as they liked. `?step` and `?exit` now apply only in dev builds and on the web preview.
4. **The Home gear opened onboarding in the App Store build.** That showed subscribers the paywall, and leaving it rewrote their routine through `saveSetup`. The gear now shows only in dev builds and on the web preview, until there is a real settings screen.
5. **Step count froze after coming back from the background.**
   - **Example:** 50 live steps, 100 more in the background, then 30 more live. The screen showed 150 instead of 180 until the next 10-second poll.
   - **Fix:** `lib/wake/steps.ts` banks the steps the watcher missed (`away`) on the first history read after a restart only. Ordinary polls still can't double-count live steps, and the cadence cap is unchanged.
   - **Tests:** 2 new.
6. **A Block now whose end iOS never delivered stayed shielded, while the app showed it as over.**
   - **Fix:** `syncLock` now tidies an expired nap (`getNap()`) on every sync.
   - **Test:** in `lock-controller.test.ts`.
7. **"Pick another way" on the walk left edit mode stuck.**
   - **What happened:** `edit('method')` set `returnTo='walk'`, but `method` wasn't in `EDITABLE`. Every later step's button said "Save" and jumped back to the walk. Tapping Back on `apps` silently restored `method: 'steps'`.
   - **Fix:** `method` was added to `EDITABLE`.
8. **The two `set-state-in-effect` lint errors in the walk (onboarding-flow).** They are now set while rendering, React's "adjusting state when a prop changes" pattern. The haptic stays in an effect, so the page no longer draws a stale frame.
9. **The Swift limit day key used `Calendar.current`.**
   - **What happened:** on a phone set to Japanese, Buddhist or Hebrew dates it wrote `0008-10-03`, `2569-10-03` or `5787-01-22`. JS never matched these, so used-up limits read as not used up and overlapping rules unshielded them.
   - **Fix:** the key is now always Gregorian.
   - **How it was checked:** the function was compiled and run with Swift 6.2 Foundation.
10. **`ShieldConfigurationExtension.swift` force-unwrapped `token!` four times.** A nil token would crash the extension, and iOS would fall back to its generic shield. It now uses `token.map { … } ?? ""`.
11. **New `features/onboarding/estimate.test.ts`.** It has 17 tests covering the value-number math: midnight and shift bedtimes, the 3 h/14 h schedule edges, zero minutes, age past the lifespan, wording, and `isInsideBedtime`. No math errors were found.

## Open: needs a decision or bigger work (most severe first)

### Revenue and App Review (before launch)

- **The release build falls back to free "dev" purchases when the RevenueCat key is missing or a placeholder** (`lib/purchases-start.ts:26`).
  - `app.json` still holds `REPLACE_WITH_REVENUECAT_PUBLIC_APPLE_KEY`.
  - `revenueCatKey` also accepts `test_` keys.
  - **Suggestion:** make a non-`__DEV__` build refuse to start the dev stub, or fail the EAS build on a placeholder or `test_` key.
- **A cancelled trial keeps working forever.**
  - Nothing ever checks the subscription again once a night is armed.
  - Already an open decision in TODO.md, but it's the biggest revenue gap.
  - **Suggestion:** at launch, disarm from the next bedtime when an armed user is no longer entitled.
- **Nap (Block now), the always-blocked list and daily limits have no subscription check.** Someone who leaves at the paywall still gets daytime blocking for free. Decide whether those count as "the lock".
- **The trial reminder assumes 7 days** (`TRIAL_DAYS` in `notifications.ts`).
  - The `longer-trial` exit arm is 14 days, so the "ends in 2 days" notification arrives on day 5.
  - A user who picked Monthly and then took the exit offer gets no reminder.
  - **Suggestion:** schedule from the entitlement's `expiresAt`.
  - Related: the reminder is only scheduled once notifications are allowed, and that's asked after the first good night. So the paywall's promise can silently not happen.
- **The legal pages still have 10 `[TODO …]` placeholders.** The privacy policy describes PostHog, which isn't in the app. Already in TODO.md.
- **The morning notification ignores proofs and emergency unlocks** (`planNotifications`).
  - The 7:00 "your apps stay asleep" fires after a 2 am emergency unlock.
  - It also fires on the free first morning after a late onboarding.
- **Purchase double-tap.** `busy` is React state, so two taps in one frame can start two purchases. Guard with a ref.
- **Ask to Buy approval** while the paywall is open doesn't move onboarding on. Onboarding never subscribes to `onEntitled`.

### Lock correctness

- **Tapping the shield does nothing on a normal morning when the app stayed closed all night.**
  - The night windows write the night shield, whose button has no action.
  - The morning words and the "Up already?" notification are only set by the app's `syncLock`.
  - **Suggestion:** the monitor extension switches the shield to the morning version at morning start (BACKGROUND_UNLOCK.md).
- **A used-up limit from yesterday is only lifted by the extension's midnight callback.** If that's missed (phone off at midnight), the limit apps stay shielded all day while the app says the limit isn't used up. Needs a JS backstop in `syncLock`.
- **Limit edits are saved before iOS accepts them** (`settleLimitChanges`, `apps-list.tsx saveAndArm`). If `startMonitoring` throws, the app shows the new limit while iOS enforces the old one, and nothing retries.
- **The Nap screen writes shield text directly and never calls `syncLock`.**
  - "Napping until …" stays on other shields after the nap.
  - It also replaces the morning tap action while the bedtime apps are still locked.
  - Home also ignores `blockNowUntil` and says the apps are awake during a nap.
- **Bedtime picker opened and closed during an emergency-paused night** re-blocks the apps straight away (`finishListEdit`, empty live list branch).
- **A nap across the fall-back DST hour** asks iOS for a ~23 h interval (`clockOf` in `startNap`).
- **JS and the extension both settling the same pending list at once** can empty the bedtime list. A missing draft is read as "emptied". Rare, but nothing would sleep. Suggest an explicit `empty` flag.

### Smaller

- **Downstairs with Motion & Fitness denied** blames the barometer. `Barometer` permissions always report granted; ask via `Pedometer.*PermissionsAsync`.
- **The wake screen keeps the display on** even in the "done" and "not morning" states.
- **"Scan your code instead"** shows with no code registered and dead-ends.
- **The You tab's passes count** can stay stale after spending a pass (no re-render on focus).
- **Home's tonight line** ignores a pending routine edit.
- **VoiceOver:** the iOS segmented control and limit menu have no group label.
- **Waitlist function** (`web/functions/api/waitlist.ts`):
  - The client-clock time trap silently drops sign-ups from phones whose clock runs fast.
  - There is no rate limit or Turnstile.
  - Exported emails starting with `=`, `+`, `-` or `@` can become spreadsheet formulas.
  - `wrangler.toml` still has the placeholder D1 id.
- **Extension build numbers** are hard-coded to 1, while EAS auto-increments the app's. Watch for an ITMS-90473 warning on the first TestFlight upload.
- **Architecture rule break:** `features/onboarding` imports `features/wake/use-step-count`, and `hooks/use-app-start` imports `features/onboarding/arm`.

## Rerunning the tools

- **Web crawl:**
  - Run `npx expo export --platform web --output-dir <dir>`.
  - Serve it with clean URLs (e.g. `serve-handler`).
  - Open every route and `/onboarding?step=<id>` in Playwright Chromium with `devices['iPhone 15']`.
  - Collect `pageerror`, console errors and failed requests.
  - WebKit won't launch on Arch (it needs Ubuntu system libraries); Chromium is fine for the preview.
- **Swift parse on Linux:**
  - Use the swift.org Ubuntu 24.04 tarball.
  - It needs `libncurses.so.6`. On Arch, symlink `/usr/lib/libncursesw.so.6` into a folder on `LD_LIBRARY_PATH`.
  - Then run `swiftc -parse <file>`.
