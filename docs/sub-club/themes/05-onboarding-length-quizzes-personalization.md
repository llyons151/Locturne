# 05 · Onboarding length, quizzes, personalization

Cross-episode synthesis of Sub Club batches 01–10. Citation format `B07 · 2025-08-06`. "(?)" = garbled-caption number. Tags: **[Hard]** / **[Freemium]** / **[Both]**. What happens *after* onboarding (aha, activation) is theme 06.

## Consensus

1. **Longer onboarding wins when each step builds belief, investment, or a visible personalised result — not by length itself.** [Hard especially]
   - Lose It!: adding questions (answers not necessarily used) raised trial take rate by double digits and improved free retention; they kept adding until returns diminished (A/B; B02 · 2023-07-12).
   - Zumba: adding interest/level questions + value interstitials + a recommended program before the app raised conversion "a lot"; contradicted team assumptions (A/B; B07 · 2025-08-06).
   - Coconote: ~doubling to ~15 screens (investment, personalisation feel, social proof) → +16% trial starts (A/B; B09 · 2026-03-18).
   - Sesame Care: 3-screen checkout → ~20–25-question intake raised conversion 40%, step completion >99% — questions built confidence the care was thorough (before/after, not clean A/B; B08 · 2025-11-26).
   - Burner: removing the "choose your number" screen lost on trial starts — picking created investment (A/B; B02 · 2022-07-13). Elevate: +25 personalisation steps cut completion but didn't hurt trial start or D1 retention (anecdote; B02).
   - Noom's ~60 steps (?) with a goal date that improves as you answer (B02 · 2022-05-25); Babbel's long "discovery stage" quiz so users "feel compelled to buy without testing" (B05 · 2024-08-07).
   - Nicole (Zumba): "we introduced friction, but it really did help."

2. **Personalise on context and emotion, and make the result visible — don't just echo answers.** [Both]
   - Nathan Hudson: a *sleep app* that asks bedtime and only personalises the reminder time is "functional but emotionally flat"; better to speak to the user's specific situation; returns diminish quickly (opinion; B06 · 2025-01-08).
   - Rise (sleep): a few screens frame sleep as "a drug", name one metric (sleep debt), then show personal sleep debt, bedtime, wake and caffeine cutoff within ~2 minutes — onboarding delivers the coaching itself (B03 · 2023-12-13; also named by Sylvain B06).
   - Opal: current screen time → mini report → lifetime projection (~22 years (?)) → "we can save you 3–5 years" → trial offer (B04 · 2024-01-10).
   - Tolan: quiz reflects the user back playfully and carries answers into first chats as "memories" (B06 · 2025-04-02; B09 · 2026-04-15). Zumba/Ladder/Natal: quiz → a recommended program or coach (B07, B03, B10). Headspace: sleep vs stress content (B07 · 2025-05-02).
   - Hudson: "A good onboarding tells a story. A great one echoes the user's story back to them."

3. **Onboarding questions double as qualification and segmentation.** [Both]
   - V1 Sports: "why are you here?" found 10–15% wanting a coach — much more likely to subscribe (observed; B05 · 2024-11-27). Rapchat: "why are you here" was the "biggest unlock" (B01 · 2021-10-06).
   - Opal: ask age and branch (older → annual paywall, students → referral/free paths); "where did you hear about us" is their most reliable attribution (B04). Marcus Burke: ask age/gender/source (B04 · 2024-04-04).
   - Petit: onboarding answers are the best way to separate high- from low-value trials (age <25, goal, prosumer, device); some add questions *to create* this variance (B07 · 2025-08-21). Ladder: by question ~6 of the web quiz they predict payment (B05 · 2024-08-21).
   - Visible deliberately screens out people the product won't help (B10 · 2026-08-19).

4. **Reduce choice and cognitive load; default the user into one commitment.** [Both]
   - Opal: every test offering more choice in onboarding failed ("fatigue budget"); auto-creating a Mon–Fri 9–5 block was a "huge win" (A/B; B04 · 2024-01-10).
   - Natal: too many programs caused decision fatigue; now route to one recommended start (B10 · 2026-05-27). Dropbox: onboard to one narrow use case (B02 · 2022-05-25). Zumba: guided programs over a library (B07).

5. **Defer account creation and other high-cost fields; keep what the user actually needs.** [Both]
   - Coconote: login first cost ~10% drop-off; moving it after the paywall was their "biggest win" (A/B/observed; B09, B10 · 2026-05-20).
   - Pray.com: a required phone number caused so much drop-off they couldn't monetise (observed; B05 · 2024-10-30).
   - Darius Contractor's framework (via Ravi Mehta): email ≈ −5 motivation points, credit card ≈ −10, password creation is among the biggest killers → use Sign in with Apple / phone OTP (B08 · 2025-11-26).
   - But: Savvy Navvy removed accounts entirely ("anonymous accounts"), results "through the roof" then decayed after rollout — users needed sync (B10 · 2026-08-05). *Defer, don't delete.*

6. **Onboarding craft: interludes, objection-matched proof, reassurance.** [Both, mostly opinion]
   - Hudson's "interludes": evidence (charts, testimonials), reassurance for known anxieties ("many people do"), functionality; time-to-result charts go here (B06).
   - Social proof should target the user's actual objection; "Join 20M users" does little for a small app (B06). Marcus Burke: show reviews from the target demographic (B04).
   - Answer the user's questions, not yours; Calm's "here to sleep, focus…?" tells users what the app does (B06).

## Contested

**A. Long quiz vs "fewer screens to the aha".**
- *Shorter:* ElevenReader — should have tested "sign-up straight into empty state" baseline first; fewer screens to hearing your own book beat goal-setting screens (retrospective, no numbers; B09 · 2026-02-04). Tinder cut 20–30 min to ~1.5–2 min and expanded the TAM (observed; B08). PhotoRoom moved the magic to 3–4 taps after guerrilla tests (B01 · 2021-09-27). Maple Media: get users in fast (B02). Welltory "magic": value for zero effort (B04).
- *Balance:* Natal keeps 10–15 questions — too many frustrates, too few confuses (B10). Petit: Noom-length works because intent is high; would fail for instant-value Photoroom (B05 · 2024-08-21). Mehta: pick from the aha moment — front-load intake if the aha is a consult, go fast if it's a conversation; avoid the "messy middle"; any length works if onboarding delivers value (Calm plays rain sounds from first open) (B08).
- Resolution: long works for *intent-building, high-consideration* products (health, fitness, learning, self-improvement); short works when the aha is instant. For a behaviour-change / wake-up product, the evidence leans long-with-visible-payoff.

**B. Label personalisation or not.** LinkedIn: "no downside to personalisation, only to doing too little" (B08 · 2025-09-17) vs TripAdvisor: silent personalised sort won, labelling it "Just for you" dropped conversion on a high-stakes choice (A/B, direction only; B08 · 2025-11-26).

**C. Web vs in-app onboarding.** Web quizzes convert better for Built With Science (~90% of paid traffic; same quiz in iOS app converted worse) (B10) and Reading.com (+50% trial, +30% paid; B07). Rise's straight port to web failed twice; web must "sell the problem", not the solution (B09 · 2026-03-05). See theme 11.

**D. Permission prompts timing.** ATT on first launch had the least impact on anything across Aperture clients (A/B; B03 · 2023-10-18) vs common "prime first" advice. Ask for widgets only after earning trust (Ladder, B09). Email capture in onboarding was welcomed (Slopes, B02). Give a clear notification opt-in/out in onboarding (Carvell, B01).

## Loss-aversion setup (see theme 09)
- Lose It: let users configure a premium feature (Weekender calorie cycling) during onboarding, then "these are Premium — continue Basic or subscribe?" Works only for features with immediate day-1 resonance; many others lost, carb goal "lost quite badly" (A/B; B02). Sylvain generalises it (B06 · 2025-03-14).
